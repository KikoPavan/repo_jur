- [ ] 1.2 Write failing tests for the per-page record contract: exactly one record per physical page with `page_number` (int), `method` (allowed engine-neutral vocabulary `texto_nativo`/`ocr_integral`/`hibrido`/`vazia`/`erro`), `char_count` (int >= 0), `warnings` (list), `errors` (list), `truncated` (bool, mandatory — missing or non-boolean is a contract error); the old field names (`run_id`, `source`, `output`, `runtime`, `ocr`, `timing` at top level, per-page `number`/`status`/`characters`/`error`) are no longer part of the accepted contract.

- [ ] 1.5 Write failing tests for the truncation signal semantics in the report: a page record with `truncated: true` is contract-valid and represents explicit authoritative known truncation; a page record with `truncated: false` represents no known truncation; the field is mandatory and always present on every emitted page record — a record lacking `truncated` is a contract error, never equivalent to `false`; the report builder never invents `truncated: true` from character counts, methods, warnings, or any other observable.
